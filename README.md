# Pittsburgh Sports Dashboard

Who the Steelers, Penguins, Pirates and Pitt play next, where and when, what the storylines are, and which players matter, built entirely from public league feeds.

- **Up next**: every team's next game, with a live countdown, venue, TV and the local start time for road games out west.
- **Storylines**: sentences generated by rules from the data (division stakes, rematches, rest and back-to-backs, road trips, form, ESPN's matchup model, special teams, weather, injuries, calendar quirks). No sentence is written by hand, so they stay true after each refresh, and each one links to the request it came from.
- **Players to watch**: injury reports and season leaders for both teams; for hockey, the goalie matchup and who has been hot over the last five games; for the Pirates' offseason, team leaders and roster moves.
- **Season**: record, standings and a game-by-game chart.
- **Around the city**: a city mood gauge, a schematic map of the three rivers with each venue's next home date, and ticking clocks since each team's last title.
- **Sources and checks**: every request behind the page, plus cross-checks that compare the same fact from two sources (ESPN against the NHL and MLB feeds).
- **Yinzer mode**: the button in the header. Yinz'll see.

## How it stays current

| Where | What | How often |
| --- | --- | --- |
| GitHub Actions (`scripts/build-snapshot.mjs`) | Fetches every feed, including the ones browsers can't call (the NHL's own API and the multi-season history), and writes `data/snapshot.json` | Every 30 minutes |
| Your browser (`assets/app.js`) | Shows the snapshot at once, then re-fetches ESPN, MLB, NWS and Open-Meteo directly | Every 5 minutes, every 30 seconds during a game |

Both paths run the same code (`assets/feeds.js`), so the browser and the snapshot can't drift apart.

## Deploy to GitHub Pages

1. Push this folder to a new **public** repository.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. **Actions → Refresh data and deploy → Run workflow.** If the run started by the first push failed at the deploy step, that was only because Pages wasn't switched on yet.
4. The site appears at `https://<your-username>.github.io/<repo>/`.

With the GitHub CLI, steps 2 and 3 are `gh api -X POST repos/OWNER/REPO/pages -f build_type=workflow` and `gh workflow run deploy.yml`.

To preview locally, run `npm run snapshot`, then `npm run serve`, and open http://localhost:8080. Run `npm test` to check that every storyline cites a real request.

## Things to know

- **The feeds are unofficial.** ESPN's and the NHL's endpoints are undocumented and can change without notice. If one breaks, that team shows "Feed unavailable" while the rest keep working. MLB's data is under MLB's terms, which allow personal, non-commercial use.
- **Scheduled runs can pause.** GitHub disables scheduled workflows in a public repo after 60 days without commits and sends an email. Re-enable it from the Actions tab. Scheduled runs can also start late when GitHub is busy.
- **Title dates are fixed and cited** in `data/history.json`. Everything else comes from the feeds, and each snapshot checks the newest Super Bowl, Stanley Cup and World Series winners from the league feeds to confirm those clocks are still running.
